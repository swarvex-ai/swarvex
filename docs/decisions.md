# Decisions

Decisions that have been made stay here with their reasons. Open questions are issues in the tracker.

| No. | Topic | Status | Decision / options |
|---|---|---|---|
| E-01 | Name and domain | decided (neVs, 25 Oct 2026) | **swarvex.ai**, subtitle "the coordination layer for agent-built software" |
| E-02 | Trust model | decided (Claude, delegated by neVs) | levels by track record, reputation tied to the person, level A tasks and credit donations from level 0 (concept §6) |
| E-03 | Engines | decided (neVs) | open per project; suitability for a swarm visible as a criterion; Godot first, more as needed |
| E-04 | Kinds of donations | decided (neVs) | agent time/tokens and credits for any service; ways "adapter" and "brief + upload" (concept §5) |
| E-05 | Workflow engine | decided (Claude) | state machine in PostgreSQL + pg-boss. No Temporal: long-running work happens at the lead/runner. Should it become necessary later, the state stays in Postgres, so no migration |
| E-06 | Identity | decided (Claude, PoC 24 Oct 2026) | **oidc-provider (panva)** in the backend instead of Zitadel: MCP clients like Claude Code register dynamically (RFC 7591) with a loopback redirect on a changing port. oidc-provider supports that; as far as we know, Zitadel does not. Plus mandatory PKCE, resource indicators (JWT tokens only for `/mcp`), device flow for the runner. People sign in through their account provider (GitHub, Codeberg, Gitea) |
| E-07 | Web framework | decided (Claude) | SvelteKit; Next.js would be equivalent, SvelteKit is leaner to self-host |
| E-08 | Object storage | decided (neVs, 25 Oct 2026) | **Garage** (S3-compatible, AGPL, actively maintained: v2.2.0 in January 2026), as a container in the compose stack, in the lab as in production. Role: **inbox** for files until acceptance, plus check reports and screenshots. The final home of every accepted contribution is the **project's Git repository** (assets via Git LFS), so projects stay viable without the platform. Text patches and metadata stay in PostgreSQL. Backups at a second provider |
| E-09 | Runner language | decided (Claude) | Go: one static binary per platform, a simple one-liner |
| E-10 | Code license of projects | **open**, per project | MIT (recommended) vs. GPLv3. Platform default is MIT |
| E-11 | Asset license | recommendation | CC BY 4.0 |
| E-12 | Contribution rule | decided (Claude) | DCO, no CLA |
| E-13 | License of the platform itself | decided (neVs, 25 Oct 2026) | **Core AGPL-3.0** (API, web, MCP gateway, task core, test pipeline, merge bot), contributions with **DCO**. **Runner, SDKs, example agents: Apache-2.0**, because the runner should run on other people's machines and in companies. No closed code in the core; self-hosting stays fully functional |
| E-14 | Lead model | decided (neVs) | Every visionary brings their own lead; the platform only provides technology and rules |
| E-16 | Rights to contributions | decided (neVs) | The platform is not responsible. Contributors confirm that they hold all rights (contribution statement); a non-binding plan note for known services; report form and takedown. Background research in `services.md`. Whether subscriptions may be used as lead/contributor is also up to the user |
| E-18 | Production hosting | decided (neVs) | The lab is built as a copy of the production server; differences only in configuration (guide in `self-hosting.md`) |
| E-17 | Pilot project | **open** | Requires the pilot game to become open source (check licenses, trademark, assets) |
| E-20 | Scope at launch | decided (neVs, 25 Oct 2026) | **Linux first, and completely.** macOS and Windows are designed in from the start (same runner code, sandbox via Podman on all three systems) and released once Linux is done |
| E-21 | Public repository | decided (neVs, 25 Oct 2026) | **GitHub**, organization "swarvex-ai". Published with a fresh history (without lab internals and committed `node_modules`), license files per E-13 |
| E-22 | Sandbox on all systems | decided (Claude) | **Podman** everywhere: rootless on Linux, `podman machine` on macOS (libkrun or Apple Hypervisor) and Windows (WSL2). No Docker Desktop (license requirement in larger companies). On Linux optionally **gVisor** (`--runtime=runsc`) against kernel bugs |
| E-23 | Releases and supply chain | decided (Claude) | GitHub Actions; **GoReleaser** for runner and test pipeline (Linux/macOS/Windows, amd64/arm64); images in **GHCR**; **cosign** keyless signing, SBOM and SLSA provenance; Renovate, govulncheck, CodeQL. Signing for macOS (Apple notarization) and Windows needs a decision once these platforms are due |
| E-24 | Operations | decided (Claude) | Observability with **OpenTelemetry** in the API, **Grafana Alloy** → Prometheus, Loki, Grafana on the server, plus an external availability check. Backups: **pgBackRest** (point-in-time recovery) and the Garage store at a second provider, restore rehearsed. Server secrets encrypted in the repository with **sops + age** |
| E-25 | Connecting agents | decided (neVs/Claude, 25 Oct 2026) | **Every agent with MCP over HTTP and OAuth must connect without special handling.** The server supports both self-registrations of the MCP specification: client ID metadata documents (standard since 2025-11-25; Claude Code, Codex, Hermes) and dynamic registration (opencode, OpenClaw). Agent = pair of person and client. Local clients with a loopback redirect count as "native" (RFC 8252, changing port). An automatic compatibility test with the real programs (`compat/`) runs before every release. For agents without OAuth or without a browser, local access through the runner (stdio) will follow |
| E-26 | Clean-room rebuilds | decided (neVs, 25 Oct 2026), implemented by Claude | The community can rebuild existing programs as open source using the **clean-room procedure**, with the usual flow through the lead and tasks. Analysis with **REA** (MIT, github.com/morluto/rea) locally in the runner sandbox on one's own lawfully acquired copy; the computing power comes from contributors. Three rooms (analysis, review, build), a wall per person and project enforced by the platform and recorded in the log; analysis only writes `specification/`, build never does. Excluded: circumventing copy protection, license checks or anti-cheat, taking over code, assets, texts or trademarks. Every clean-room project needs `original.legal_basis`. **Before the first public clean-room project, an expert reviews procedure and texts** (copyright, EU Software Directive Art. 5(3)/6, license terms, patents) |
| E-27 | Open source as a stance | decided (neVs, 25 Oct 2026) | swarvex is open source and stands up for it: "Open source is the only way we will deal with software in the future." The platform itself (AGPL/Apache, E-13) and all public projects are under OSI licenses; every tool and repository used is credited with its license (`THANKS.md`, "Open source" page). **Open source only (neVs, 25 Oct 2026): swarvex only has public projects under an OSI license, no private projects, not even for money.** |
| E-28 | Free project environment | decided (neVs, 26 Oct 2026), implemented by Claude | **Any language, any engine, as simple as possible.** The visionary does not have to set anything up: swarvex detects the project type (Godot, Node, Python, Rust, Go, .NET, Java), uses an existing dev container or a `swarvex.yaml` (`template` or own `image`, `setup`, `build`, `test`, `dir`, `protected`). Setup with network but without agent and keys; agent and tests without network. Runner and test pipeline use the same package; `swarvex env` checks a project locally. Environment files, project rules, CI and licenses are locked for contributions |
| E-29 | Repository language | decided (neVs, 26 Oct 2026) | **English** for the repository, interfaces (CLI, MCP tools, HTTP API, configuration) and commits. Documentation in English with a German translation (`docs/de/`, `lead/de/`). Internal code names (database, variables) follow gradually |
